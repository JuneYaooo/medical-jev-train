# 输入格式与运行范围

medical-jev-4b 使用一次模型前向计算，对给定候选输出选择和完整概率分布。发布配置支持 **2–52 个候选、完整输入最多 8,192 token**。

## 候选选项

每题的 `criteria` 将语义键映射为选项文字。推理时按输入顺序将候选映射到 A–Z、a–z，共 52 个单 token 符号，读取答案位置对应的分数并做 softmax，返回原来的语义键。无需生成解释或连续解码长答案。

52 是这套单 token 选项编码的容量，不是底座只能理解 52 个候选。更多候选需要相应的编码、训练和评测支持；当前发布接口不覆盖 148 候选的中医证型题。

## 输入长度

token 长度包含材料、判断要求、全部候选和聊天模板，由底座 tokenizer 计算；它不等于汉字数。8,192 是当前发布配置的运行范围，不代表底座的理论上下文上限。

| 验证输入 | 结果 |
|---|---|
| 外部基准中的 49 候选题，共 100 题 | 全部完成打分，模型答对 61 题 |
| 外部基准中的 1,747 token 题 | 完成打分，模型未答对 |
| 合成标签定位输入：2,040、4,092、8,187 token | 三项均完成且答对；batch 1，最长输入峰值显存约 9.09 GiB |
| 52 候选边界 | 返回选择及 52 个候选的概率 |
| README 六个场景案例 | 输出与保存的示例结果一致 |

长输入验证使用简单标签定位任务，不能证明任意 8K 医疗病例的准确率或大批量运行效果。显存不足时可使用 `--batch-size 1`。

环境为 RTX 5090、PyTorch 2.8.0+cu128、FP16。参数与检查结果见 [运行记录](results/v1/input-limit-check.json)，完整效果见 [评测报告](RELEASE_V1.md)。
